## Known gaps (verifiable only in a live preview battle)

1. **#1 route-state retention across the battle→result unmount.** The core of the
   fix — `onMissed` accumulating into `pvp.live.$matchId.tsx` `missed` useState so
   the list survives `LivePvpBattleScreen` unmounting when the **opponent resolves
   the match** — lives in realtime/route wiring with no unit-test seam. Verify live:
   lose a Nearby/Training match **by the opponent's answer** and by **no-answer/
   timeout**, confirm the defeat screen shows a complete missed list both ways.
2. **#1 single `onMissed` call site covers all 3 wrong paths.** The runner routes
   real-wrong / no-answer / personal-timeout through one guarded `else`
   (dedup via `lastResolvedIdxRef`). Not unit-reachable without a runner harness —
   verify no duplicate/blank rows live.
3. **#3 dual-fire, toast announce, and attribution.** Removing Gate A/Gate B, both
   abilities folding into `dmg`/`selfDmg`, both toasts firing, the info popover
   listing **both** chips, server report of the type-ability id, and **no
   double-count** in attribution — all live-loop/effect wiring. The data-layer test
   proves the precondition (both ids resolve); the actual stacking + announce +
   attribute must be confirmed with a **legendary partner in a live battle**.
4. **Solo lose screen visual parity** — assert it renders (footer path tested), but
   pixel-parity vs. the pre-refactor markup is an eyeball check on preview.
5. **No component render/interaction harness in the repo** (node env, no jsdom/RTL).
   Adding one is out of QA's ownership (config/deps) — flagged for DevOps if richer
   component tests are wanted later.
