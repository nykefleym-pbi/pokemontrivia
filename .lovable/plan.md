# Guest Mode + Expanded Avatars Plan

## 1. Guest Mode = one-tap start

On the splash screen, "Guest Mode" no longer routes to the Create Trainer flow. Instead it immediately:

1. Picks a random Pokémon from the full list and uses its name (with a numeric suffix if needed, e.g. `Pikachu-42`) as the trainer name.
2. Picks a random Pokémon avatar (any gen).
3. Picks a random Trainer sprite from the new Bulbagarden roster.
4. Marks the user as a **guest** (`isGuest: true` in the store) and onboarded.
5. Navigates straight to `/battle` and auto-starts the 20-question battle (skips intermediate menus).

Guests get the same battle/store as normal players. They can still convert to a "real" trainer later via Profile (rename / repick avatars).

### Guest-specific question history rule

- Today the deduplication keeps the last 500 question hashes for everyone.
- Requirement is *"Guest Mode only repeats after 500 questions."* That matches the current behavior, but to make it explicit and to satisfy the rule even if we change the cap for normal players later, we'll:
  - Keep `MAX_SEEN_HASHES_GUEST = 500` (FIFO).
  - Keep `MAX_SEEN_HASHES_USER = 500` (unchanged) — same cap, same behavior. Normal users can be tuned independently later.
- The `flowSeed` already passed to `/api/trivia-batch` continues to ensure the *same* question doesn't reappear in the *same flow* once recycling kicks in.

## 2. Pokémon roster — all generations

Replace the hand-written Gen 1 list with a build-time generated list covering Pokédex IDs **1–1025** (through Gen 9 / current National Dex).

- A one-shot script (`scripts/build-pokemon.ts`, run once locally and committed) fetches `https://pokeapi.co/api/v2/pokemon/{id}` for each id and writes `src/lib/pokemon-data.generated.ts` with `{ id, name, slug, types }`.
- Sprite source switches to **pokemondb** per the user's snippet:
  - Primary: `https://img.pokemondb.net/sprites/black-white/normal/{slug}.png` for slugs available in BW (Gen 1–5).
  - For later gens, use pokemondb's newer pack: `https://img.pokemondb.net/sprites/scarlet-violet/normal/{slug}.png`.
  - Fallback chain: `home/normal/{slug}.png` → PokeAPI sprite → generic Poké Ball icon.
  - The script records which sprite pack to use per id so the runtime just builds the right URL.
- `searchPokemon()` and the picker keep the "first 9 then full search up to 30" pattern.
- The "evolved or solo" enemy list expands to use only fully-evolved/no-evolution Pokémon across all gens (also generated by the script using PokeAPI's `evolution_chain` data).

## 3. Trainer roster — scraped from Bulbagarden

The 4 category pages have direct image URLs of the form
`https://archives.bulbagarden.net/media/upload/{a}/{ab}/{filename}.png`
(verified — example `Spr RS Maxie.png`).

A second one-shot script (`scripts/build-trainers.ts`) scrapes:

- `Category:Generation_III_Trainer_sprites`
- `Category:Generation_IV_Trainer_sprites`
- `Category:Generation_V_Trainer_sprites`
- `Category:Pokémon_Masters_Trainer_sprites`

…following the `next page` pagination links, parses each `gallerybox` `<img src>`, and writes `src/lib/trainer-data.generated.ts`:

```ts
export interface TrainerSprite {
  id: string;        // slug from filename, e.g. "rs-maxie"
  name: string;      // pretty, e.g. "Maxie (R/S)"
  url: string;       // full archives.bulbagarden.net URL
  gen: 3 | 4 | 5 | "masters";
}
export const TRAINER_SPRITES: TrainerSprite[] = [ ... ];
```

The runtime reads from this static list. No live scraping at runtime.

- Replace `TRAINER_SPRITES` (string[]) and `trainerSpriteUrl()` in `src/lib/game-data.ts` with imports from the generated file. `trainerSprite` in the store becomes the slug; rendering uses the URL from the lookup, so no broken `play.pokemonshowdown.com` requests for `florian`/`juliana`.
- Picker: first 9 by default, search across full list capped at 30 — unchanged UX.
- Enemy generation (`pickRandomEnemy`) draws from the same list and uses each trainer's pretty name as the displayed name.
